A registry row, owner alone, geographic X threshold, HQ berth or type string does not establish military control. Do not broaden Policy or consult hidden enemy facts to find candidates.

No cargo/crew/inventory/recursive mass inspection is needed by presentation. Health/condition does not claim crew, fuel or order readiness.

Other permitted CARRIERs retain the existing abstract proxy behavior: Rear, Construction, other types, destroyed/cleared/noncanonical T01 and controller-only friendly rows whose actual owner differs. CONTACT remains report position/confidence only. Preserve the legacy abstract fallback and its geographic visibility rule; this increment does not certify or redesign that rule or cleared-wreck Policy. PERSON, PLACE and enemy inspection semantics remain unchanged.

## Events, cues and teardown

Membership/state reconciles once at initial bind and the existing coalesced session state/Policy refresh. entity_moved refreshes only the cached affected hull and cached dependents of moved ancestors; canonical move_entity already updates heading. Existing PLACE movement is not accepted by move_entity. Keep explicit keyed dependencies rather than per-frame holder/roster inspection.

The narrow canonical facing-write path is Records.Entity.facing_degrees default0, move_entity deriving facing from nonzero endpoint travel, and set_vehicle_facing normalizing supplied finite degrees for an actual surviving specified hull. Initial vehicle creation retains default0; binding/replacement reads that initial current pose. Movement already emits entity_moved after committing position/heading: do not add a second facing notification or duplicate per-move redraw. Pure set_vehicle_facing currently writes facing_degrees and logs _event; _event merely appends history and emits no signal. Propose one narrow vehicle_facing_changed(id) signal at that setter ONLY when normalized finite yaw actually changes, consumed only for the affected cached model. Preserve the setter's current validity, return and event-log semantics even for an unchanged normalized yaw. Reuse vehicle_damaged for actual damage and existing session state boundaries for membership, repair/clear/receipt changes. Do not promise refresh after private unsignalled field writes or add timed pose/ledger polling. Disconnect all old ledger/presenter subscriptions and remove world/cue references before freeing nodes on removal/replacement.

Keep the truck visible at strategic scale with one bounded field_t01_cues Control using cached anchors and current camera/view/viewport invalidations, following the existing PERSON pattern without replacing it or introducing a generic cue framework. Proposed cue is a cyan 12x8px rectangle centered on the actual ground anchor, filled far and hollow at camera.size<=40; actual immobilized condition is amber. Selected actual ID uses the existing ring/text convention. Same projected visibility cache drives truck drawing and picking; offscreen/behind/invalid models cannot be edge-picked. Draw reads no ledger/camera state. Existing RTS min10/max6500, pitch -65 degrees, height3400, reachable pan and UI modes remain unchanged. One proposed size20 image must show the actual exterior, cue and current inspection; source completion alone is not appearance acceptance.

## Acceptance and limits

The existing initial military T01 becomes one selected-art model at canonical terrain position/yaw, with no second proxy or rear detailed body for that ID. One genuine canonical endpoint update and then one actual setter-only yaw update refresh the cached field transform without a forced roster rebuild or command notification. The same current ID is selected through the existing inspection path; no orders or authority change. Detailed and strategic presentation remain coherent with the current permitted population; unsupported carriers and reported contacts stay abstract. Surviving means actual hull health>0; uncleared means actual wreck_cleared=false. Immobilization remains a distinct actual damage_immobilized flag, not a PERSON assignment/death or readiness inference.

Only brief source/parser/map checks are allowed in this planning pass. Before implementation, Lead resolves this concrete population/cue/event proposal and owns any game-meaning objection from Designer. The eventual single fixed observation uses one existing actor, one endpoint, one setter yaw and one image under unchanged35s rendered child/45s wrapper; it does not rerun the old Rear receipt/commissioning observation, PERSON correction, asset/bounds audit or a state matrix. Other membership/lifecycle/receipt/condition distinctions are source-reviewed, not exercised. No native input/FPS, fleet performance, supply/crew/combat acceptance or complete vehicle parity claim.
