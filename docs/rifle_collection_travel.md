# Rifle collection travel

## Outcome and plan — 31 October 2026

The Designer requires a feasible travel outcome for both collection and return to the latest acknowledged operation. For a journey over 600 m, command requests actual transport when its arrival and complete pickup/boarding/travel/dismount time is faster than safe walking. Absent or disadvantageous transport permits a safe foot march with an explicit ETA. A busy freight vehicle cannot be silently taken, and unavailable transport must not cause an indefinite wait.

The next increment composes the existing T02 transport, orders, route continuations and physical supply owners. It adds no inventory, navigation framework, global scheduler or worker thread. Actual parent acknowledgement names the selected vehicle's collection assignment while the Rifle's current operation remains authoritative; a transport order must not become a cache of an obsolete objective.

- Trace current cohort, real pickup and destination, available hull/crew/load, route and fallback, applicable delivered hazards, fuel/reserve, physical commitments, boarding/dismount time and command delivery before choosing a mode.
- Keep ETA calculation pure and bounded across returned frames. Project actual prospective passenger mass for selection only; every real admission/departure retains fresh authoritative physical checks.
- Let the existing military transport owner retain pickup, boarding, travel, dismount, interruption and the same job/hull/person identities. No logical travel state claims that people have arrived.
- Keep survival, emergency reassignment, casualty/leadership/cohesion, current orders and Pause above routine collection. Interruption preserves actual occupants, fuel, goods and commitments.
- Show going to supply, awaiting pickup, collecting and returning to duty with real travel mode, ETA and useful blockers. Source ownership and implementation details stay in documentation.

Lead owns the execution/intent/clock/UI connection. Developer B owns the small composed Rifle travel decision/controller. Developer C owns necessary existing transport admission/authority primitives. Shared APIs are aligned before dependent edits, then reviewed and integrated promptly.

Acceptance is one brief direct demonstration of the new long-distance connection, including actual pickup/boarding/travel/dismount and current-operation return. It must not replay the passed short-foot flow or become a coverage matrix. No local engine, regression writing/suite, broad scenario or profiler. Necessary direct checking stays on GitHub under the existing short deadline. Other GDD work and native desktop responsiveness remain open.

## Implemented connection

The composed RifleSupplyTravel owner measures each current carrier's safe foot route and eligible same-company T02 candidates. Quotes include empty pickup, actual sequential boarding approaches, two seconds per boarding/dismount and prospective actual passenger mass on the loaded route/fallback. Current crew, payload, commitments, known danger and fuel plus 25 percent reserve constrain the choice. Busy, freight-laden, unsafe, slower or unapproved vehicles do not create an indefinite wait when measured safe foot travel remains possible.

The selected vehicle's actual parent issues a named Move by Transport order with the exact current Rifle operation, cycle, leg, cohort, pickup and destination. Its real delivery/acknowledgement is separate from the Rifle's operation. Pure calculation creates no physical claim. At running settled boundaries, metadata markers describe actual stopped positions without moving people or hulls. Existing transport then owns real pickup, boarding, fresh loaded departure, travel and dismount. Supply trips finish at actual dismount; the fallback remains validated but no untravelled empty return is labelled complete.

Current command changes invalidate private proposals and retain any admitted physical job for fresh same-job reassessment. Partial dismount finishes at its actual stop before a new destination can be considered. Pinned, Broken, leadership, casualty, activity and custody requirements remain. Source review covered these boundaries; the direct flow below does not establish every interruption outcome.

Base alternates the new pure planner with existing transport planning, using one shared 128-unit/4,000-microsecond cooperative allowance per returned frame. Ready foot choices and acknowledgement waits release the clock; Pause prevents physical admission while allowing pure work. Execution installs only fresh captured foot plans and observes existing movement rather than restarting it. Native captures, copies, local approaches and knowledge checks retain indivisible costs; neither allowance nor a yielded frame is a hard latency guarantee. Ordinary inspection shows mode, destination, real transport state, current shortage, a remaining arrival estimate where known, and an explicit pending estimate otherwise.
