# Warehouse recovery menu proposal

UI/UX consultation,10November2026. The original proposal is retained below. Remaining aboard-cargo return now has
source implementation on the supplier feature branch, with one safe-withdrawal/actual-exit refund episode passed at4992164. Native menu and full-loop acceptance remain open.
Clear bay staging now has source implementation for actual non-timber whole
packages, one finite batch and safe stop; one scoped clearance/recollection episode passed at2d61539.
Warehouse reload remains proposed only. This introduces no
new developer, screen framework, art, animation or approval gate.

Keep the actual above-truck cause primary: Full, Preparing storage, blocked
access and unavailable haulers are distinct owner facts. A full-storage hint can
direct the player to Supply Table delivery details or warehouse E inspection;
do not advertise an E interaction on trucks unless implemented.

Existing delivery details can add Return cargo for the same still-present truck.
Show actual undelivered packages/kg, **estimated goods refund paid only after
actual exit**, and the retained transport fee. Default Keep delivery; explicit
Confirm return revalidates the same truck/cargo/quote. Explain that new unloading
stops, safe carries finish, then the truck departs. Accepted work shows finishing
carries/preparing return/departing with refund pending, followed by the actual
once-only refund on exit. Optional warehouse reload is separate and offered only
when actual eligible whole packages and real packing capacity exist.

Warehouse E inspection can add one compact Clear a bay section using the existing
option control. Select one actual bay, list its whole package/kg batch and quote
the entire6×4m staging reservation before pickup. Confirmation explains that the
source bay is held against refilling, real workers move goods and another batch
cannot start until staging is actually empty. Default Keep bay; explicit Confirm
bay clearance. No instant capacity gain, deletion, refund or automatic overflow.

Staging feedback distinguishes empty/reserved/receiving/occupied and actual moved
versus remaining package counts. Disable another confirmation with the actual
occupied/in-use/changed/route/capacity reason. Preserve selection on refusal and
prevent duplicate submission while accepted work is active. Warehouse stock and
staging stock remain separate. Owners supply all quantities, timing and release
facts; the menu does not manufacture them.

Lead owns implementation and physical quotes/admission. Designer owns gameplay
semantics. This proposal supplements the accepted warehouse design and the
pre-code recovery diagram; it is not evidence of implemented recovery.
