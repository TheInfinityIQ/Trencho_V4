## Run and observe

Normal launch retains the original G03 entry and adds **G04 R01 Production** to its review selector. The new scene owns one accepted G03 rear simulation with its actual people, jobs, stores, ledger and clock, plus one R01 activity. The declared initial depot holds only 2 M01 + 1 M02; two requested operators must report. There is no input refill, free finished rifle or separate production clock. Switching reviews starts another declared setup; it is not a transfer or a way to clear a live bay.

1. Advance 300 seconds without hauling. Two actual operators are present at F04, but production reports Missing Inputs and hauling shortage. No input is consumed or work earned.
2. Assign Hauling 1. Actual source reservation, pickup, walking and drop deliver the exact ingredients. Local unreserved owned stock, actual present operators and free full 4 kg output capacity permit one atomic start. Reporting and hauling intervals never earn manufacturing work. Time advances may pass several real events; the batch start receipt records the actual deposit/start time.
3. Two operators supply 40 operator-work seconds in 20 active simulation seconds from actual start. Pause R01 or block output to retain work, consumed receipt and output promise; resume/restore legal access to continue. Releasing operators preserves work and gives Missing Labour until real eligible people are present again.
4. Exactly one empty E01 appears in workshop_output, occupying 4 kg, without ammunition or automatic delivery. Inspect its physical count, work/receipt and completed batch. Continuous mode waits for more real ingredients; none are silently created. Cancel stops continuous requests, loses already consumed inputs, keeps finished output and releases only that batch's unfulfilled promise once. Resume explicitly enables requests again.

Output controls demonstrate active-promise protection: Try 3 kg or an E01-excluding filter is refused atomically while the 4 kg promise exists. Access loss is permitted and pauses work. Other filter edits preserve existing contents and request actual relocation. Scrollable people/job details show holders/positions, actual duty, carry/pending handoff and delivered/in-flight counts; they are inspections, not another inventory.

## Ownership and event boundaries

`r01_production.gd` owns enabled/pause state, one active batch ID, required/completed work, input-consumption receipt, stable future output ID and completed/cancelled history. It holds a weak reference to its owning rear simulation, avoiding a lifetime cycle. It does not own people, goods or time. Ordinary unissued rifles use the ledger's existing counted equipment-stock representation, as in G01; this slice does not issue a loaded weapon to a person.

`rear_simulation.gd` retains the common event loop and capacity accounting. An optional production activity contributes its next completion boundary; work accrues using eligible actual operators before physical staffing/handling transitions settle at that boundary. Real source deposits can start the batch only after drop; newly reported operators earn no retroactive work. Output promises join actual inbound haul promises in free-space checks. Capacity/filter edits are validated before any access/capacity/filter mutation when an active production promise is involved. Null production leaves the accepted staged G03 cases and their zero-production evidence unchanged.

The ledger's `consume_local_batch` validates every positive whole ingredient across owned local unreserved stacks before mutating any of them. R01 first secures full output space, consumes the complete batch once, and stores the receipt. Missing/foreign/reserved/remote/carried input cannot provide a partial start. The canonical 3 kg input → 4 kg output abstraction is preserved without invented waste or material. Completion rechecks the same space promise and creates the stable output ID once before releasing only that promise. Fully worked but invalid completion retains work/promise without output; restoring legal completion does not demand additional operator-work credit; no overflow or unborn-output recovery pile is used.

Facility pause, missing labour/access and output blockage preserve consumed inputs/work/promise. Explicit cancellation records loss of those already-consumed inputs rather than refunding them, leaves existing finished goods untouched, clears only its own promise and disables continuous requests. Repeated cancellation/completion cannot repeat creation, consumption or release.
