# Synchronous route tile reuse

The lead's bounded native probe at 6.017 simulated seconds measured a 13,084 ms route-admission stall after the observation/ledger fixes. TerrainWorld.route repeatedly resolved each occupied metre cell through the same explicit-cell/last-region lookup for closure, support, overlay and adjacent height checks.

The route now resolves each occupied tile once, retaining a read-only tile reference as the value of its existing local occupied-cell dictionary. The public support method retains its bounds check and uses a pure support-from-tile helper. Each invocation still returns a fresh rule; cell-local field multipliers and bridge caps never share mutable support results. Eligible finalized rules can subsequently share a read-only reference as described below. Traversal, cuts, support/load/width checks, first refusal and height-edge iteration order are unchanged. No result or tile cache survives the synchronous call, and no global spatial index is introduced.

`route_tile_reuse_regression.gd` retains independent pre-change cell, support and route lookup/admission code from 01942b3. Only unchanged geometry and aggregation helpers are inherited. It compares complete result dictionaries, first refusals and raw world state, and counts lookups to require one resolution per occupied cell in the same order. Coverage includes catalogue cases, layered/half-open regions and explicit overrides, paint/region/support changes between queries, bridge approaches/load/width, fresh field effects, causeways, height discontinuities, rotated sweeps and long Farmland lanes. The older sweep oracle alone would not detect a lookup bug because it inherits route admission; this oracle does not.

Source-only contribution under the user's desktop resource restriction: no local engine, test, import or profiling runs. Runtime correctness, performance improvement and playable responsiveness are pending remote verification. Departure/load/revision validation in the transport owners is unchanged; no admitted plan is reused across physical loading or later world changes.

## Measured hot-loop follow-up

The later 42d remote profile measured route aggregation at 1.675 seconds and 644,256 height evaluations at 0.379 seconds within 3.718 seconds of route work. The separate candidate from ae4b74d holds each active interval's rule once, preserving every min/max operation and surface-order step. Height-edge checks skip a pair only when `is_same(here,there)` proves both dictionaries are the same raw tile reference. `_tile_height` is a pure read of that tile and the same point, so both evaluations have identical results; distinct references retain all original endpoint checks and refusal order. This is no value-equality shortcut or persistent memo.

[Godot 4.7's is_same contract](https://docs.godotengine.org/en/4.7/classes/class_@globalscope.html#class-globalscope-method-is-same) specifies reference identity for Dictionary. The legacy route oracle remains untouched. Additional assertions compare shared nonzero gradients, equal-but-distinct painted tiles, changed adjacent tile/region heights, completed overlay heights and a changed overlay step against it. Height-call counters require zero evaluations only for an entirely shared tile, and retained evaluations on distinct tile edges. The existing independent aggregation oracle still verifies exact aggregation arithmetic. This candidate is source-only and awaits remote correctness and timing evidence; integration remains the lead's decision after the next profile.

## Consecutive finalized-rule candidate

The separate candidate based on 7993b7d still computes fresh support, applies every field effect and finalizes every crossing/approach cap before considering sharing. Only consecutive occupied cells whose raw tile dictionaries are identical references can reuse the previous finalized rule reference. Any matched field-effect area, including one irrelevant to the movement class, or any executed approach-cap branch excludes both sides of that adjacency from sharing. Crossing caps are properties of the identical raw tile and are finalized before sharing. Rule references are read-only after finalization and local to one synchronous route. Distinct equal tiles are not shared, and nothing persists across queries.

Aggregation skips only consecutive identical rule references in the existing ordered active list. It retains all cuts, parts and arithmetic after aggregation and performs the original operations for every differing rule. The pinned engine's [minf/maxf entry points](https://github.com/godotengine/godot/blob/ed1daf0bf/core/variant/variant_utility.cpp#L639) call [MIN/MAX](https://github.com/godotengine/godot/blob/ed1daf0bf/core/typedefs.h#L130), which select the left operand only on a strict less/greater comparison. After the first application with operand b, repeating the same operand either retains the prior selected value or selects the same b again. Ties (including signed zero) and unordered NaN comparisons select b; repeating identical b preserves its value. This argument only removes consecutive repetitions; A/B/A remains ordered because B can change the result. Surface membership/addition is likewise unchanged by a consecutive identical surface.

The two legacy oracle bodies remain untouched. Added admission coverage captures finalized rule identities and counts fresh support calls; it covers unmodified shared tiles, field effects, equal approach caps, equal-but-distinct explicit cells, completed crossing caps and changed caps on later queries. Aggregation coverage supplies repeated references, A/B/A, distinct equal rules, changing active membership, duplicate/sub-EPS cuts, signed zeros, infinities and NaNs in all four numeric operands. Exceptional outputs are compared by serialized bytes rather than NaN-sensitive dictionary equality. These cases have been authored but not run locally. Correctness, timing and integration remain pending GitHub verification; no speedup is claimed.

## Per-route region candidates

The fa67 profile measured `cell` at 0.820 seconds within 3.266 seconds of route work. This separate candidate computes the same clamped integer floor/ceil endpoints previously used directly by the nested cell loops, then builds a descending list of base-region references that can contain a coordinate in that exact scan rectangle. The cell/SAT traversal and occupied-cell lookup order are unchanged. A private route lookup checks explicit cells first, scans candidates in original last-region-wins order using the original point-membership test, then returns a fresh TR01 dictionary. Public `cell()` remains unchanged. No candidate list survives the synchronous route call, and no terrain/support/height/aggregation rule changes.

Only positive Rect2i regions with nonwrapped increasing endpoints are filtered against a positive scan rectangle. The pinned engine's [Rect2i intersection and point-membership implementation](https://github.com/godotengine/godot/blob/ed1daf0bf/core/math/rect2i.h#L48) uses the same half-open endpoints: outside-touching rectangles cannot contain an integer scan coordinate. Floating-point, empty, negative-size or wrapped-end rectangles remain candidates without normalization or exclusion. The original point-membership behavior still decides their tile; a later shadowing region avoids invoking unsupported negative-size membership in the regression fixture.

The independent legacy cell/support/admission and legacy aggregation oracle bodies remain unchanged. Only the actual route-lookup counting hook moves from public cell to the new helper. Added cases compare defaults, all four outside-touching scan edges, internal half-open edges, explicit priority, descending candidate identity/order, moved/changed/new regions between queries, fractional rectangles with and without an integer member, conservatively retained unusual rectangles and negative-coordinate rotated lanes. Existing generated rotated and long authored Farmland lanes also compare complete results and first refusals with the independent admission oracle. Source-only candidate: no local engine, import, test or profile launches; correctness and cost, including candidate construction overhead, require GitHub verification before integration.

## Homogeneous interval sweep candidate

The ae3 profile still measured route aggregation at 1.084 seconds total (1.039 self) over 100 calls. This separate candidate accepts only a nonempty list whose every interval shares one finalized rule reference, whose bounds are finite floats with start strictly below end, and whose cuts are finite. Other inputs retain the existing ordered active-list sweep. After sorting the same pending starts and cuts, homogeneous spans activate the same starts through each midpoint and retain the maximum activated end. An occupied span exists exactly when at least one start has activated and that maximum reaches the midpoint. This preserves gaps and inclusive touching endpoints rather than assuming complete coverage. A single representative index then enters the unchanged aggregation body, which already skips consecutive identical rules. Every original numeric accumulator, min/max operand order, surface step, part and total remains unchanged; the coverage maximum never enters returned arithmetic. The explicit activation check also avoids treating an initial negative-infinite overflowed midpoint as occupied before any finite start activates.

Both independent legacy oracle bodies remain unchanged. Added aggregate cases cover disconnected spans, unsorted overlap, nesting, touching at a sampled midpoint, duplicate/sub-EPS cuts, empty input, distinct equal rule references, fallback for degenerate/inverted/infinite/non-float bounds, and signed zero/infinity/NaN rule operands alongside gaps. NaN bounds and nonfinite cuts assert conservative guard rejection without assigning new semantics to those unsupported sweep inputs. Admission coverage verifies that shared base/crossing rules select the shortcut and modified/explicit-cell rules retain the ordinary sweep, alongside the existing complete legacy comparisons. This is a source-only candidate: no local engine/import/test/profile runs, no speedup claim, and no change to the currently pending verification batch. GitHub correctness and cost measurements remain required before adoption.

Successful full-route oracle comparisons require exactly one context construction, retain complete result/first-refusal checks and include the existing obstacle, region, closure, slope, bridge, effect, rotated and authored long lanes. This source-only candidate has not been run locally. Four small dictionaries are allocated per context; each cell adds context-entry reads and one private helper dispatch. ## Per-probe region candidate reuse

The a7b actual-combat profile measured terrain observation at 6.505 seconds, its 4,600 probes at 6.426 seconds and 679,492 cell calls at 5.138 seconds. Probe does not call support: its repeated lookup work is the full base-region scan for each crossed cell. The separate candidate retains both endpoint ground calls, range/outside checks and obstacle iteration in their original order. It then generates the original ray segments once and builds one descending candidate list from the exact integer cells already in that array. It reuses the existing explicit-cell-first, original has_point, last-region-wins lookup within the unchanged segment loop. There is no lookup of later tiles after a budget break, no persistent or cross-probe cache, and no extra shared context API. Public cell/ground/probe/observe signatures remain unchanged. All height/gradient/overlay, eye/muzzle, vegetation/canopy, distance/budget, volume, threshold and first-blocker arithmetic stays untouched; the final detached block_cell still uses the original unrestricted cell lookup.

Only positive nonwrapped integer region rectangles are excluded by intersection. Fractional, empty, negative-size or overflow-end regions are retained, and an unrepresentable ray-cell bound retains all regions. The existing terrain regression now retains the complete independent a7b cell, ground, tile-height, ray traversal, volume interval, probe and observe algorithms. It compares every serialized output field and ordered segment, along with unchanged terrain state, across catalogue cases and focused near/zero/EPS/range/outside, endpoint overlays, sloped height planes, vegetation budgets, equal-distance volume order, drone/muzzle independence, half-open/touching/fractional regions, explicit overrides, changed regions/tiles/obstacles on the same world, and rotated/negative/grid-edge rays. Counters verify one context, descending region identity/order and no later tile resolution after a vegetation budget break. This is source-only work: no local engine/import/test/profile was launched. The extra ray-bound scan and candidate construction require GitHub runtime parity and net cost measurements before adoption.
