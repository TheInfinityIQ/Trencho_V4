# Synchronous route tile reuse

The lead's bounded native probe at 6.017 simulated seconds measured a 13,084 ms route-admission stall after the observation/ledger fixes. TerrainWorld.route repeatedly resolved each occupied metre cell through the same explicit-cell/last-region lookup for closure, support, overlay and adjacent height checks.

The route now resolves each occupied tile once, retaining a read-only tile reference as the value of its existing local occupied-cell dictionary. The public support method retains its bounds check and uses a pure support-from-tile helper. Each invocation still returns a fresh rule; cell-local field multipliers and bridge caps never share mutable support results. Eligible finalized rules can subsequently share a read-only reference as described below. Traversal, cuts, support/load/width checks, first refusal and height-edge iteration order are unchanged. No result or tile cache survives the synchronous call, and no global spatial index is introduced.

`route_tile_reuse_regression.gd` retains independent pre-change cell, support and route lookup/admission code from 01942b3. Only unchanged geometry and aggregation helpers are inherited. It compares complete result dictionaries, first refusals and raw world state, and counts lookups to require one resolution per occupied cell in the same order. Coverage includes catalogue cases, layered/half-open regions and explicit overrides, paint/region/support changes between queries, bridge approaches/load/width, fresh field effects, causeways, height discontinuities, rotated sweeps and long Farmland lanes. The older sweep oracle alone would not detect a lookup bug because it inherits route admission; this oracle does not.

Source-only contribution under the user's desktop resource restriction: no local engine, test, import or profiling runs. Runtime correctness, performance improvement and playable responsiveness are pending remote verification. Departure/load/revision validation in the transport owners is unchanged; no admitted plan is reused across physical loading or later world changes.

## Measured hot-loop follow-up

The later 42d remote profile measured route aggregation at 1.675 seconds and 644,256 height evaluations at 0.379 seconds within 3.718 seconds of route work. The separate candidate from ae4b74d holds each active interval's rule once, preserving every min/max operation and surface-order step. Height-edge checks skip a pair only when `is_same(here,there)` proves both dictionaries are the same raw tile reference. `_tile_height` is a pure read of that tile and the same point, so both evaluations have identical results; distinct references retain all original endpoint checks and refusal order. This is no value-equality shortcut or persistent memo.

[Godot 4.7's is_same contract](https://docs.godotengine.org/en/4.7/classes/class_@globalscope.html#class-globalscope-method-is-same) specifies reference identity for Dictionary. The legacy route oracle remains untouched. Additional assertions compare shared nonzero gradients, equal-but-distinct painted tiles, changed adjacent tile/region heights, completed overlay heights and a changed overlay step against it. Height-call counters require zero evaluations only for an entirely shared tile, and retained evaluations on distinct tile edges. The existing independent aggregation oracle still verifies exact aggregation arithmetic. This candidate is source-only and awaits remote correctness and timing evidence; integration remains the lead's decision after the next profile.

## Consecutive finalized-rule candidate

The separate candidate based on 7993b7d still computes fresh support, applies every field effect and finalizes every crossing/approach cap before considering sharing. Only consecutive occupied cells whose raw tile dictionaries are identical references can reuse the previous finalized rule reference. Any matched field-effect area, including one irrelevant to the movement class, or any executed approach-cap branch excludes both sides of that adjacency from sharing. Crossing caps are properties of the identical raw tile and are finalized before sharing. Rule references are read-only after finalization and local to one synchronous route. Distinct equal tiles are not shared, and nothing persists across queries.

Aggregation skips only consecutive identical rule references in the existing ordered active list. It retains all cuts, parts and arithmetic after aggregation and performs the original operations for every differing rule. The pinned engine's [minf/maxf entry points](https://github.com/godotengine/godot/blob/ed1daf0bf/core/variant/variant_utility.cpp#L639) call [MIN/MAX](https://github.com/godotengine/godot/blob/ed1daf0bf/core/typedefs.h#L130), which select the left operand only on a strict less/greater comparison. After the first application with operand b, repeating the same operand either retains the prior selected value or selects the same b again. Ties (including signed zero) and unordered NaN comparisons select b; repeating identical b preserves its value. This argument only removes consecutive repetitions; A/B/A remains ordered because B can change the result. Surface membership/addition is likewise unchanged by a consecutive identical surface.

The two legacy oracle bodies remain untouched. Added admission coverage captures finalized rule identities and counts fresh support calls; it covers unmodified shared tiles, field effects, equal approach caps, equal-but-distinct explicit cells, completed crossing caps and changed caps on later queries. Aggregation coverage supplies repeated references, A/B/A, distinct equal rules, changing active membership, duplicate/sub-EPS cuts, signed zeros, infinities and NaNs in all four numeric operands. Exceptional outputs are compared by serialized bytes rather than NaN-sensitive dictionary equality. These cases have been authored but not run locally. Correctness, timing and integration remain pending GitHub verification; no speedup is claimed.
