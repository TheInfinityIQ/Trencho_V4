# Continuing resource operations

Source implementation on the PR86 continuation branch, 31 October 2026; behavior verification remains Lead-owned.

The authored opening's real troop lifts, first resource capture and delivered completion report remain prerequisites. After that report reaches each army's own root, `battlefield/resource_operations.gd` proposes continuing resource operations to `opening_policy.gd`. Opening alone issues and relays orders through the current real parents. An external company order is not replaced. The initial Rifle HQ guard is excluded from the helper's force.

The helper consumes only root-delivered reports and contacts, declared Resource positions, and actual own capability. A bounded append cursor consumes the report list, which OrderService populates only after actual root delivery; in-transit rows remain with its pending owner. Resource ownership is learned from an actual friendly capture report, or from a local Rifle leader within 25 m with real sight. Opening sends the latter observation from the actual observing squad through the existing Progress report chain, preserving the actual submission time. The helper retains the actual observer and position as observation metadata. Unchanged local ownership observations are deduplicated. Distant live ownership, objective enemy participant arrays, unseen health and inventory never supply operation eligibility.

Resource candidates reuse GDD §16.3 priorities: protect a known-owned resource threatened by delivered hostile information at85; seize a locally reported neutral resource at80; probe an unconfirmed resource approach at40. The score subtracts0.1 per measured approach second and30 times delivered caution strength divided by assigned eligible Rifle strength. Ties prefer shorter travel, then the oldest unserved objective. A known-owned resource without a reported threat is not another Protect candidate.

Existing military capability, cohesion and order-service strength queries gate the assigned force. Observed relevant armour excludes this infantry-only slice, which has no penetrating support plan. The1.3 ordinary attack threshold, current delivered threat/ownership and own capability are checked again before proposal selection. Execution retains actual local ratios, withdrawal, pinned/broken, survival, supply and per-person movement authority. A proposal grants neither movement nor capture.

One aggregate cooperative terrain-work allowance per existing policy tick measures straight-lane foot approaches and supply/fallback corridors. It does not run one full deadline per candidate and does not promise a hard4ms frame bound. Actual own leaders supply mass and start positions for conservative foot estimates; their ordinary progress does not continually invalidate the whole search. Terrain revision invalidates geometry. Current delivered mines/fire and actual capability are rechecked at selection; Execution plans and checks every real walk from its actual position.

The last acknowledged operation continues while planning. Completed operations or meaningful delivered changes trigger reconsideration, with a10-second review/mission hold. A still-feasible operation is retained against changes within its priority class, avoiding reversals for tiny score differences. Higher resource priority, completion or lost feasibility can produce a new named operation. Existing order holds, receipt and acknowledgement still apply.

Blue uses its existing delivery/rally corridor. Red uses its real HQ stock and dismount fallback positions; this names a geometric corridor and does not implement Red forward delivery or refill. No missing stock is credited, no vehicle is moved, and no target, encounter, winner or HQ assault is forced. Unsupported routes/capability hold and report a reason. Broader route finding, tactical transport allocation, the full commander catalogue and Red autonomous logistics remain outside this increment.
